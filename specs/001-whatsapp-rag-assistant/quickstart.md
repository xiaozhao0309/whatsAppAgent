# Quickstart & Validation: WhatsApp 企业知识问答助手 1.0

**Date**: 2026-08-02 | **Spec**: [spec.md](./spec.md) | **Contract**: [contracts/webhook.md](./contracts/webhook.md)

本文档是端到端验证指南，证明功能按规格工作。不含完整实现代码，实现细节在 tasks.md 与代码中。

---

## 1. 前置条件

- Python 3.10+，已创建并激活虚拟环境。
- 已安装依赖：`pip install -r requirements.txt`（新增测试需安装 `pytest`）。
- 已配置 `.env`（从 `.env.example` 复制），至少包含：
  - Twilio：`TWILIO_ACCOUNT_SID`、`TWILIO_AUTH_TOKEN`、`TWILIO_WHATSAPP_NUMBER`
  - Ark：`ARK_API_KEY`、`ARK_MODEL`、`ARK_BASE_URL`
  - 值班号码：`ON_DUTY_NUMBER`（转人工用；不配则转人工优雅降级）
- 单 worker 运行（会话/幂等/限流在进程内存）：**必须**使用 `--workers 1`。

## 2. 启动与导入

```bash
# 导入/重建知识库（单实例本地 Qdrant，导入时不要与其他写进程并发）
python scripts/ingest.py

# 启动服务（单 worker）
uvicorn app.main:app --reload --port 8000 --workers 1
```

健康检查：

```bash
curl -s http://localhost:8000/health
# 期望：{"status":"ok","kb":{"collection":"enterprise_kb","points":<N>,"accessible":true}}
```

## 3. 自动化测试（单元）

```bash
pytest -q
```

覆盖：会话截断/过期与滑动刷新、限流窗口、幂等去重、指令识别、切片边界、pipeline 阈值拒答与历史拼接（mock 检索与 LLM）。

## 4. 端到端验证场景

下列场景通过 WhatsApp（或 `/ask` 调试接口）验证。

### 4.1 核心问答（US-1，FR-001~004）
- **步骤**：问"年假有几天？"
- **期望**：基于知识库回答，末尾标注来源（如 `参考来源: hr_faq.md`），并提示可回复 👍/👎。

### 4.2 拒答不编造（US-2，FR-002/005）
- **步骤**：问与知识库完全无关的问题（如"今天股价多少"）。
- **期望**：返回统一拒答话术，不编造，不标注虚假来源。

### 4.3 空库提示（FR-006）
- **步骤**：清空 collection 后提问。
- **期望**：回复"知识库尚未就绪"。

### 4.4 多轮追问（US-3，FR-009~013）
- **步骤**：问"年假有几天？"，再问"那病假呢？"
- **期望**：第二问正确理解"那"指代休假类并作答。
- **重置**：发"重新开始"，收到已重置确认；之后的追问不再带旧上下文。

### 4.5 轮数/字符截断（FR-011/012）
- **步骤**：连续发起超过 10 轮对话，或发送制造超长历史的内容。
- **期望**：仅最近 10 轮、且上下文不超过 2000 字符送入模型（可通过日志中记录的上下文长度验证）。

### 4.6 跨天/会话过期（US-4，FR-010/014）
- **步骤（测试手法）**：临时把 `SESSION_TTL_SECONDS` 设为很短（如 5 秒），对话后等待过期再发消息。
- **期望**：收到"已重新开始"提示，不基于旧上下文作答。
- **跨设备**：同一 WhatsApp 账号在手机和桌面端分别发消息，上下文连续。

### 4.7 转人工（US-5，FR-015~019）
- **步骤 A**：发"转人工"。
- **期望**：收到"已通知值班人员"；`ON_DUTY_NUMBER` 收到含客户问题与最近对话的通知；若主号失败且配了备用号，备用号收到。
- **步骤 B**：连续 2 次提问知识库外问题。
- **期望**：第 2 次拒答后主动提示并触发转人工通知。
- **降级**：未配置值班号码时，不崩溃，提示暂无值班人员并记录告警。

### 4.8 欢迎与帮助（US-6，FR-020/021）
- **步骤**：用新号码首次发任意消息；再发"帮助"。
- **期望**：首次收到欢迎语+示例；"帮助"收到功能说明。

### 4.9 反馈（US-7，FR-022/023）
- **步骤**：回答后回复 👍，再连续回复多次 👎。
- **期望**：日志记录一次反馈（问题/答案/来源/时间），重复表情不重复记录。

### 4.10 幂等去重（FR-027）
- **步骤**：用相同 `MessageSid` 重复 POST `/webhook`（可手动构造表单）。
- **期望**：只产生一次后台处理与一次回复，第二次被丢弃。

### 4.11 限流（FR-025）
- **步骤**：临时把 `RATE_LIMIT_PER_MINUTE` 设为 2，1 分钟内从同一号码发第 3 条。
- **期望**：第 3 条收到"操作过于频繁，请稍后再试"，不触发问答。

### 4.12 超长消息（FR-026）
- **步骤**：发送超过 `MESSAGE_MAX_CHARS` 的文本。
- **期望**：收到"消息过长，请精简后再发"，不进入检索/LLM。

### 4.13 异常兜底（FR-029，宪法原则 IV）
- **步骤**：配置错误的 Ark key 后提问。
- **期望**：收到友好错误提示，终端日志有 `logger.exception` 堆栈，服务进程不崩溃。

### 4.14 日志与脱敏（FR-030/031）
- **步骤**：正常问答后查看日志。
- **期望**：每条含 request_id、脱敏 WAID、命中数、top_score、是否回答、耗时；不含完整号码、密钥、Auth Token。

### 4.15 webhook 即时响应（FR-028，宪法原则 II）
- **步骤**：POST `/webhook` 并计时。
- **期望**：无论 LLM 多慢，接口在毫秒级返回 200，答案随后异步到达。

## 5. 上线前标定（非自动化）

- **相似度阈值**：用真实知识库与典型问题集，分别统计命中/无关问题的分数分布，调整 `RAG_SCORE_THRESHOLD`（默认 0.5 仅为起点），目标满足 SC-001/SC-003。
- **话术确认**：欢迎语、帮助、拒答、转人工、限流、错误提示文案由业务方确认。
- **值班号码**：确认 `ON_DUTY_NUMBER`（及备用号）可正常接收。
- **进程守护**：部署环境配置自动重启（如 systemd），满足异常恢复。
- **Twilio 正式号码**：客户正式服务使用 WhatsApp 商业号码；Sandbox 仅用于开发测试。
