# WhatsApp 企业知识问答助手 — 时序图

本文档基于当前代码（[backend/app/main.py](../backend/app/main.py)、[backend/app/rag_client.py](../backend/app/rag_client.py)、[ai_service/app/main.py](../ai_service/app/main.py)、[ai_service/app/rag/pipeline.py](../ai_service/app/rag/pipeline.py)、[backend/app/handoff.py](../backend/app/handoff.py) 等）绘制核心流程的 Mermaid 时序图。

系统是**两个 FastAPI 服务**：

- **后端**（端口 8000）：webhook、幂等/限流、会话、指令、转人工、回发 WhatsApp。
- **AI 服务**（端口 8001）：embedding、Qdrant 检索、LLM 生成。
- 两者通过同步 HTTP（`POST /answer` 等）通信，是唯一耦合点。

流程要点：
- 同步阶段（webhook 内立即执行）：幂等检查，然后立即返回 HTTP 200。
- 后台阶段：同一用户在**用户锁内串行**处理：长度→限流→指令→会话→**HTTP 调 AI 服务**→回发。

## 1. 主流程：正常问答（命中知识库）

```mermaid
sequenceDiagram
    autonumber
    participant U as 客户 WhatsApp
    participant T as Twilio
    participant W as 后端 /webhook
    participant IG as IdempotencyGuard
    participant UL as 用户锁
    participant H as 后端 _handle
    participant RL as RateLimiter
    participant CMD as commands
    participant S as SessionStore
    participant RC as rag_client
    participant AI as AI 服务 /answer
    participant P as RAG pipeline
    participant E as embeddings
    participant Q as Qdrant
    participant LLM as Ark LLM
    participant CH as channel(Twilio)

    U->>T: 发送问题
    T->>W: POST /webhook (MessageSid, From, Body)
    W->>IG: seen_or_mark(MessageSid)
    alt 已见过(重复投递)
        IG-->>W: true
        W-->>T: 200 空响应(丢弃)
    else 首次
        IG-->>W: false
        W->>W: add_task(_handle_serialized)
        W-->>T: 200 空响应(立即)
        T-->>U: （等待回复）

        W->>UL: 获取该用户锁
        activate UL
        UL-->>W: 加锁
        W->>H: _handle(sid, from, body)
        activate H
        H->>RL: allow(wa_id)
        RL-->>H: true
        H->>CMD: parse_command(body)
        CMD-->>H: None(普通问题)
        H->>S: state(wa_id)
        S-->>H: active
        H->>S: build_context(wa_id)
        S-->>H: 历史 turns
        H->>RC: answer(question, history)
        RC->>AI: POST /answer (JSON)
        activate AI
        AI->>P: answer(question, history)
        activate P
        P->>E: embed_one(question)
        E-->>P: 向量
        P->>Q: search(向量, top_k)
        Q-->>P: hits(带 score)
        Note over P: 最高分 ≥ 阈值
        P->>LLM: chat(messages=系统+历史+问题)
        LLM-->>P: 答案
        P-->>AI: AnswerResult(answered, sources, top_score)
        deactivate P
        AI-->>RC: 200 JSON(reply, sources, status, top_score)
        deactivate AI
        RC-->>H: AnswerResult
        H->>S: record_hit / add_turn(user+assistant)
        H->>CH: send_whatsapp(答案+来源+反馈提示)
        CH->>T: REST API 发消息
        T->>U: 收到回答
        deactivate H
        deactivate UL
    end
```

## 2. 无答案：拒答 + 连续 2 次自动转人工

```mermaid
sequenceDiagram
    autonumber
    participant U as 客户
    participant H as 后端 _handle
    participant S as SessionStore
    participant RC as rag_client
    participant AI as AI 服务
    participant Q as Qdrant
    participant HO as handoff
    participant CH as channel
    participant D as 值班号码

    Note over U,D: 第 1 次答不出
    U->>H: 无关问题
    H->>RC: answer()
    RC->>AI: POST /answer
    AI->>Q: search()
    Q-->>AI: hits
    alt 最高分 < 阈值 或 LLM 自陈无内容
        AI-->>RC: status=no_match
    end
    RC-->>H: AnswerResult(no_match)
    H->>S: add_turn(user / 拒答话术)
    H->>S: record_miss()
    S-->>H: miss_streak = 1
    H->>CH: 发送"没找到，可换问法或转人工"
    CH-->>U: 拒答回复

    Note over U,D: 第 2 次仍答不出 → 自动转人工
    U->>H: 另一个无关问题
    H->>RC: answer()
    RC->>AI: POST /answer
    AI-->>RC: status=no_match
    RC-->>H: AnswerResult(no_match)
    H->>S: add_turn / record_miss()
    S-->>H: miss_streak = 2
    H->>CH: 发送拒答话术
    H->>HO: trigger_handoff(reason=auto_no_answer)
    HO->>S: 取最近上下文
    HO->>CH: send_whatsapp(ON_DUTY_NUMBER, 问题+上下文)
    CH->>D: 收到转人工通知
    alt 主号失败且配了备用号
        HO->>CH: 发送 ON_DUTY_FALLBACK_NUMBER
    else 未配置/都失败
        HO-->>H: false
    end
    H->>CH: 发送"已通知值班人员"/"暂无值班人员"
    CH-->>U: 收到确认
```

## 3. 指令分支（帮助 / 重置 / 问候 / 反馈）

> 指令完全在**后端**处理，不调用 AI 服务。

```mermaid
sequenceDiagram
    autonumber
    participant U as 客户
    participant H as _handle
    participant CMD as parse_command
    participant S as SessionStore
    participant CH as channel

    U->>H: 发送消息
    H->>CMD: parse_command(body)
    CMD-->>H: Command(type, value)

    alt type = help
        H->>CH: 发送 HELP 菜单
    else type = reset
        H->>S: reset(wa_id)
        H->>CH: 发送"已重新开始"
    else type = greeting（你好/hi/在吗）
        alt 会话已存在
            H->>S: add_turn(寒暄)
            H->>CH: 发送"Hi! How can I help?"
        else 新用户
            H->>S: add_turn(欢迎语)
            H->>CH: 发送 WELCOME 欢迎语
        end
        Note over H: 不调用 AI 服务
    else type = feedback (👍/👎)
        H->>S: try_mark_feedback(wa_id, value)
        alt 本轮首次反馈
            S-->>H: true
            Note over H: 记录结构化日志(rating)
        else 已评价过
            S-->>H: false(去重)
        end
        H->>CH: 发送"感谢反馈"
    else type = handoff
        H->>H: _do_handoff(customer_request)
    end
    CH-->>U: 收到对应回复
```

## 6. RAG 内部时序（AI 服务 pipeline.answer）

```mermaid
sequenceDiagram
    autonumber
    participant Caller as ai_service /answer 路由
    participant P as pipeline
    participant ST as store
    participant E as embeddings
    participant Q as Qdrant
    participant LLM as Ark

    Caller->>P: answer(question, history)
    P->>ST: count_points()
    alt 知识库为空
        ST-->>P: 0
        P-->>Caller: AnswerResult(empty_kb)
    else
        P->>E: embed_one(question)
        E-->>P: qvec
        P->>Q: query_points(qvec, top_k)
        Q-->>P: hits(score, payload)
        alt 无命中
            P-->>Caller: AnswerResult(no_match)
        else 最高分 < 阈值
            P-->>Caller: AnswerResult(no_match, top_score)
        else 相关性达标
            P->>P: 拼 system(资料+来源要求) + history + 当前问题
            P->>LLM: chat.completions.create()
            LLM-->>P: 回复文本
            alt 回复含"do not contain relevant content"
                P-->>Caller: AnswerResult(no_match)
            else 正常
                P->>P: 截断到 answer_max_chars
                P-->>Caller: AnswerResult(answered, reply, sources, top_score)
            end
        end
    end
```

## 7. 启动流程（两个服务各自 lifespan）

```mermaid
sequenceDiagram
    autonumber
    participant CLI1 as uvicorn ai_service:8001
    participant LSA as ai_service lifespan
    participant ST as store
    participant E as embeddings

    participant CLI2 as uvicorn backend:8000
    participant LSB as backend lifespan
    participant RC as rag_client

    par AI 服务启动
        CLI1->>LSA: app startup
        LSA->>ST: ensure_collection()
        Note over ST: 不存在则创建 collection
        LSA->>E: embed_one("warmup")
        Note over E: 预加载模型，避免首条消息卡顿
        E-->>LSA: 就绪
        LSA-->>CLI1: 开始服务(8001)
    and 后端启动
        CLI2->>LSB: app startup
        LSB->>RC: health()
        RC->>LSA: GET /health
        alt AI 已就绪
            LSA-->>RC: ok + KB 点数
            RC-->>LSB: reachable
            Note over LSB: 记日志"AI service reachable"
        else AI 未就绪
            RC-->>LSB: RAGServiceError
            Note over LSB: 记 warning，不阻塞启动<br/>后续按请求重试
        end
        LSB-->>CLI2: 开始服务(8000)
    end
```

> 启动顺序建议：**先 AI 服务，后后端**；即使后端先启动也不会崩，只是 health 检查记一条 warning，每次请求时会重试。


## 关键设计要点

- **webhook 立即 200**：所有耗时操作（HTTP 调用 AI 服务、LLM、回发）都在后台，避免 Twilio 超时重试。
- **同步幂等**：MessageSid 检查在加入后台任务之前完成，杜绝重复回复。
- **用户级串行锁**：同一用户的消息排队处理，防止并发导致重复欢迎语、会话错乱。
- **两道拒答防线**：检索分数低于阈值不调 LLM；LLM 自陈无内容也按拒答处理。
- **转人工三场景**（决策在 `handoff_policy.decide()`）：客户发 `agent` → 回复 `CONTACT_PHONE_NUMBER` 并（若配置）通知值班号；连续 `HANDOFF_MISS_THRESHOLD` 次答不出、连续 `HANDOFF_ERROR_THRESHOLD` 次 AI 服务报错/超时 → 回复联系电话，**不自动通知**值班人；回答了但 `top_score < LOW_CONFIDENCE_SCORE` 时只在答案后追加"回复 agent 联系人工"提示。
- **一次冷却**：`HandoffStore` 记录会话已给过联系方式，TTL 内或 reset 前后续失败只回普通兜底文案，不反复刷电话号码。
- **后端单 worker**：会话/幂等/限流/handoff 状态都在后端进程内存，必须 `--workers 1`。
- **故障隔离**：AI 服务挂了后端不崩，返回友好错误；`GET /health` 暴露降级状态。
- **契约边界**：两服务只通过 `/answer` 的 JSON 契约耦合，AI 内部（模型/切片/prompt/阈值）可独立演进。
