# WhatsApp 企业知识问答助手 — 架构图

本文档基于当前代码（`backend/` + `ai_service/` 两个 FastAPI 服务）绘制系统架构，使用 Mermaid 语法。配合 [时序图.md](时序图.md) 和 [开发决策与使用记录.md](开发决策与使用记录.md) 阅读。

2026-08-13 由单进程拆分为 monorepo 双服务，便于后端与 AI 两人分工。两服务唯一耦合是 `POST /answer` 的 HTTP/JSON 契约。

- 后端同学与 AI 同学只需约定 `/answer` 契约即可并行开发。

## 4. 进程内运行时结构

后端与 AI 服务是**两个独立的 uvicorn 进程**，各自持有模块级单例。

```mermaid
graph TB
    subgraph BP["后端进程 uvicorn backend:8000 (--workers 1)"]
        direction TB
        subgraph BASGI["FastAPI / ASGI"]
            BROUTES["路由<br/>POST /webhook<br/>POST /ask<br/>GET /health<br/>POST /admin/ingest"]
            BLIFE["lifespan<br/>rag_client.health() 探活"]
        end
        subgraph BGLOB["模块级单例"]
            SESS["session_store"]
            IDEM["idempotency"]
            RL["rate_limiter"]
            ULOCK["_user_locks<br/>dict[WAID→Lock]"]
            RC["rag_client<br/>(requests, 30s 超时)"]
        end
        subgraph BBG["BackgroundTasks 线程池"]
            T1["_handle_serialized(用户A)"]
            T2["_handle_serialized(用户B)"]
        end
    end

    subgraph AP["AI 服务进程 uvicorn ai_service:8001"]
        direction TB
        subgraph AASGI["FastAPI / ASGI"]
            AROUTES["路由<br/>POST /answer<br/>POST /ingest<br/>GET /health"]
            ALIFE["lifespan<br/>ensure_collection()<br/>embed_one('warmup')"]
        end
        subgraph AGLOB["模块级单例"]
            QCLIENT["QdrantClient<br/>(本地文件单例)"]
            EMB["SentenceTransformer<br/>(lru_cache 单例)"]
        end
    end

    BROUTES --> BBG
    BBG --> SESS
    BBG --> IDEM
    BBG --> RL
    BBG --> ULOCK
    BBG --> RC
    BLIFE --> RC
    RC -->|"HTTP"| AROUTES
    ALIFE --> QCLIENT
    ALIFE --> EMB
    AROUTES --> QCLIENT
    AROUTES --> EMB

    classDef be fill:#e6f4ea,stroke:#34a853
    classDef ai fill:#fef7e0,stroke:#f9ab00
    class BROUTES,BLIFE,SESS,IDEM,RL,ULOCK,RC,T1,T2,BBG,BGLOB,BASGI be
    class AROUTES,ALIFE,QCLIENT,EMB,AGLOB,AASGI ai
```

**关键点**：
- 后端的会话/幂等/限流/用户锁是**模块级单例**，所以后端必须 `--workers 1`；多 worker = 多份内存，去重/会话/限流会失效。
- AI 服务无会话状态（Qdrant client 和 embedding 模型是无状态共享资源），worker 数相对自由，1.0 仍用单 worker。
- 不同用户的后台任务可并行，但**同一用户的任务被用户锁串行化**。
- 后端通过 `rag_client` 同步调用 AI 服务，调用发生在后台线程内，不阻塞 webhook 的 200 响应。

## 5. 部署架构（1.0 本地单实例，两个进程）

```mermaid
graph LR
    subgraph CLOUD["公网"]
        NGROK["ngrok<br/>(本地开发临时隧道)"]
        LB["负载均衡 / 反向代理<br/>(生产可选)"]
    end

    subgraph HOST["服务器 / 本机"]
        BE["uvicorn backend<br/>app.main:app --workers 1<br/>端口 8000 (+ systemd 守护)"]
        AI["uvicorn ai_service<br/>app.main:app --workers 1<br/>端口 8001 (+ systemd 守护)"]
        subgraph LOCAL["本地资源 (归 AI 服务)"]
            QLOCAL[("Qdrant 文件<br/>ai_service/data/qdrant")]
            MODEL["本地 embedding 模型<br/>~80MB"]
        end
    end

    subgraph SAAS["外部 SaaS"]
        TW["Twilio"]
        ARK["火山方舟 Ark"]
    end

    DEV["开发者"] -.->|"本地开发"| NGROK
    PROD["生产入口"] -.-> LB

    NGROK --> BE
    LB --> BE
    BE -->|"HTTP /answer (内网)"| AI
    AI --> QLOCAL
    AI --> MODEL
    BE -->|"HTTPS"| TW
    AI -->|"HTTPS"| ARK
    TW <-->|"WhatsApp"| WA["客户手机"]

    classDef ext fill:#e8f0fe,stroke:#4285f4
    classDef host fill:#e6f4ea,stroke:#34a853
    classDef ai fill:#fef7e0,stroke:#f9ab00
    classDef saas fill:#fce8e6,stroke:#ea4335
    class NGROK,LB,DEV,PROD,WA ext
    class BE host
    class AI,QLOCAL,MODEL ai
    class TW,ARK saas
```

**部署要点**：
- 两个进程分别启动、分别守护（systemd/supervisor）；任一崩溃由守护进程自动拉起。
- AI 服务只需在内网对后端可达，**不必**暴露公网。
- 后端 `.env` 放 Twilio 凭据和 `ON_DUTY_NUMBER`；AI 服务 `.env` 放 `ARK_API_KEY`——密钥分离。
- AI 服务挂掉时后端不崩，`/health` 返回 `degraded`，问答回友好错误提示。

**升级到多副本时**（未来 2.0）：后端把 `SessionStore`/`IdempotencyGuard`/`RateLimiter` 的内存实现换成 **Redis** 即可水平扩展；AI 服务把 Qdrant 从本地文件改为 **Qdrant server** 并加多副本。业务编排与 `/answer` 契约基本不动。

## 6. 数据流：一条消息的完整旅程

```mermaid
flowchart TD
    START([客户发送 WhatsApp 消息]) --> A[Twilio POST 后端 /webhook<br/>MessageSid, From, Body]
    A --> B{同步幂等<br/>seen_or_mark?}
    B -->|已见过| DROP([返回 200 丢弃])
    B -->|首次| C[add_task 后台处理<br/>立即返回 200]

    C --> LOCK[获取该用户锁<br/>同一用户串行]
    LOCK --> LEN{长度 ≤ 上限?}
    LEN -->|超长| S_LONG[回发 MESSAGE_TOO_LONG]
    LEN -->|是| RL{限流允许?}
    RL -->|超限| S_RL[回发 RATE_LIMITED]
    RL -->|是| CMD{是指令?}

    CMD -->|help/reset/greeting/<br/>feedback/handoff| DOCMD[执行指令分支<br/>回发对应文案]
    CMD -->|普通问题| SESS{会话状态?}

    SESS -->|absent 新用户| WELCOME[回发欢迎语]
    SESS -->|expired 过期| RESTART[回发已重新开始]
    SESS -->|active| CALLAI
    WELCOME --> CALLAI[rag_client.answer<br/>POST /answer]

    CALLAI --> NET{AI 服务可达?}
    NET -->|连接失败/超时| ERR[回发 responses.ERROR<br/>后端不崩]
    NET -->|可达| AIPIPE[AI 服务 pipeline.answer]

    AIPIPE --> KB{知识库为空?}
    KB -->|是| EKB[回发 EMPTY_KB]
    KB -->|否| EMB[embed 问题]
    EMB --> SEARCH[Qdrant 检索 top_k]
    SEARCH --> SCORE{最高分 ≥ 阈值?}
    SCORE -->|否| NOMATCH[拒答 NO_ANSWER<br/>miss_streak+1]
    SCORE -->|是| LLM[拼 system+历史+问题<br/>调 Ark LLM]
    LLM --> SELF{LLM 自陈无内容?}
    SELF -->|是| NOMATCH
    SELF -->|否| OK[截断答案 + 附来源 + 反馈提示]

    NOMATCH --> STREAK{miss_streak ≥ 2?}
    STREAK -->|是| HANDOFF[触发转人工<br/>通知值班号]
    STREAK -->|否| SEND
    HANDOFF --> SEND[回发客户]
    OK --> WRITETURN[写入会话 user+assistant]
    WRITETURN --> SEND
    DOCMD --> SEND
    S_LONG --> SEND
    S_RL --> SEND
    ERR --> SEND
    EKB --> SEND
    S_END([结束])
    SEND --> S_END

    classDef decision fill:#fef7e0,stroke:#f9ab00
    classDef action fill:#e6f4ea,stroke:#34a853
    classDef stop fill:#fce8e6,stroke:#ea4335
    class B,LEN,RL,CMD,SESS,NET,KB,SCORE,SELF,STREAK decision
    class DROP,S_END,ERR stop
```
